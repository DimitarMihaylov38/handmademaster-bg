# HandmadeMaster BG

HandmadeMaster BG е React SPA приложение за представяне на български майстори и техните ръчно изработени продукти.

Приложението позволява на посетители да разглеждат каталог с продукти и профили на майстори, а регистрираните потребители могат да създават и управляват собствен профил, да добавят продукти и да запазват любими изделия.

# Functional Guide

## 1. Project Overview

### Application Name

**HandmadeMaster BG**

### Application Category / Topic

Online catalog / platform for handmade products and Bulgarian craftspeople.

### Main Purpose

HandmadeMaster BG предоставя място, в което български майстори могат да представят своите ръчно изработени изделия и информация за своята дейност.

Посетителите могат да разглеждат продукти и профили на майстори, а регистрираните потребители могат да управляват собствен профил, да добавят и редактират продукти и да съхраняват любими изделия.

Приложението е информационен каталог и не съдържа checkout или система за директни плащания.

## 2. User Access & Permissions

### Guest (Not Authenticated)

Потребител без активна сесия може да:

- разглежда началната страница;
- разглежда каталога с всички продукти;
- отваря детайлна страница на продукт;
- разглежда всички майстори;
- отваря профил на конкретен майстор;
- използва търсене и филтриране;
- използва филтри по категория;
- използва филтри по статус;
- използва минимална и максимална цена;
- регистрира нов акаунт;
- влиза в съществуващ акаунт.

Публичните маршрути са:

- `/`
- `/products`
- `/products/:productId`
- `/masters`
- `/masters/:masterId`
- `/login`
- `/register`

Guest потребител няма достъп до частните функционалности за създаване, редактиране и управление на данни.

### Authenticated User

Регистрираният и логнат потребител има достъп до:

- `/profile`
- `/profile/edit`
- `/favorites`
- `/products/create`
- `/products/:productId/edit`

Логнат потребител може да:

- редактира собствения си профил;
- добавя и сменя профилна снимка;
- създава продукт;
- качва снимка на продукт;
- редактира собствен продукт;
- сменя снимката на собствен продукт;
- изтрива собствен продукт;
- добавя чужди продукти към любими;
- премахва продукти от любими;
- разглежда своя списък с любими продукти;
- излиза от профила си.

Редактирането и изтриването на продукт са позволени само на неговия собственик.

## 3. Authentication & Session Handling

### Authentication Flow

Приложението използва **Supabase Authentication**.

При зареждане на приложението Auth Context проверява дали има активна Supabase потребителска сесия.

Authentication състоянието се споделя между компонентите чрез **React Context API**.

При успешна регистрация:

1. Създава се потребител в Supabase Authentication.
2. Създава се profile запис за потребителя.
3. След успешното приключване потребителят може да използва authenticated функционалностите.

При успешен вход:

1. Supabase валидира email и парола.
2. Получава се потребителска сесия.
3. Auth Context обновява authentication състоянието.
4. Частните страници и authenticated навигацията стават достъпни.

При logout:

1. Извиква се Supabase sign-out функционалността.
2. Активната сесия се прекратява.
3. Authentication състоянието в Context се обновява.
4. Частните навигационни елементи вече не се показват.

### Session Persistence

Supabase управлява потребителската сесия.

При refresh на страницата приложението проверява съществуващата Supabase сесия и възстановява текущия потребител.

React Context използва тази информация, за да поддържа правилното authentication състояние в цялото приложение.

## 4. Routing Structure

Приложението използва **React Router** за client-side navigation.

### Main Routes

- `/` — Начална страница
- `/products` — Каталог с всички продукти
- `/products/:productId` — Детайлна страница за продукт
- `/products/create` — Добавяне на нов продукт
- `/products/:productId/edit` — Редактиране на собствен продукт
- `/masters` — Списък с всички майстори
- `/masters/:masterId` — Профил на конкретен майстор
- `/login` — Вход
- `/register` — Регистрация
- `/profile` — Потребителски профил
- `/profile/edit` — Редактиране на профил
- `/favorites` — Любими продукти
- `*` — 404 страница

### Parameterized Routes

Приложението използва URL parameters в:

- `/products/:productId`
- `/products/:productId/edit`
- `/masters/:masterId`

Идентификаторът от URL адреса се използва за зареждане на конкретния запис от Supabase.

### Route Guards Logic

Използвани са два route guard компонента.

#### AuthGuard

Позволява достъп само на authenticated потребители.

Ако guest потребител опита да отвори частна страница, се пренасочва към:

`/login`

#### GuestGuard

Позволява достъп до `/login` и `/register` само на guest потребители.

Ако вече логнат потребител отвори тези маршрути, се пренасочва към началната страница.

## 5. List → Details Flow

### Catalog / List Page

Страницата `/products` зарежда продуктите от Supabase и ги представя като продуктов каталог.

За всеки продукт могат да бъдат визуализирани основни данни като:

- изображение;
- име;
- категория;
- статус;
- цена.

Каталогът позволява:

- търсене по име;
- филтриране по категория;
- филтриране по статус;
- минимална цена;
- максимална цена;
- комбиниране на филтри;
- изчистване на филтрите.

### Details Page

При избор на продукт потребителят преминава към:

`/products/:productId`

`productId` се получава от URL параметрите и се използва за извличане на конкретния продукт от Supabase.

Детайлната страница показва разширена информация за избрания продукт.

Ако текущият потребител е собственик на продукта, той получава достъп до действията:

- `Редактирай`
- `Изтрий`

Логнат потребител, който не е собственик, може да добави продукта към любими.

Подобен List → Details flow се използва и при майсторите:

- `/masters`
- `/masters/:masterId`

## 6. Data Source & Backend

Приложението използва **Supabase** като Backend-as-a-Service.

Supabase предоставя:

- PostgreSQL Database;
- Authentication;
- Row Level Security;
- Storage;
- remote data communication чрез Supabase JavaScript SDK.

Данните не са hardcoded.

Продуктите, профилите и любимите изделия се съхраняват постоянно в hosted Supabase база данни.

## 8. Data Operations — CRUD

Приложението поддържа пълен CRUD за `products`.

### Create

Логнат потребител може да създаде продукт чрез:

`/products/create`

Потребителят попълва формата, избира изображение и изпраща данните към Supabase.

`owner_id` свързва продукта с текущия потребител.

### Read

Продуктите се извличат от Supabase и се визуализират в:

- `/products`
- `/products/:productId`
- `/favorites`
- `/masters/:masterId`

Публичните потребители могат да разглеждат каталога и детайлните страници.

### Update

Само собственикът на продукта може да отвори:

`/products/:productId/edit`

След записване на промените данните се обновяват в Supabase и потребителят вижда актуализираната информация.

### Delete

Само собственикът на продукта може да го изтрие.

Преди изтриване се изисква потвърждение.

След успешно изтриване продуктът вече не присъства в каталога.

## 9. Row Level Security

Supabase Row Level Security е активиран.

Основните правила са:

- публично четене на продукти;
- публично четене на профили;
- потребител може да редактира само собствения си профил;
- потребител може да добавя продукт само от свое име;
- потребител може да редактира само собствен продукт;
- потребител може да изтрива само собствен продукт;
- потребител може да вижда само собствените си favorites;
- потребител може да добавя favorite само за себе си;
- потребител може да изтрива само собствен favorite.

Така owner permissions се прилагат не само в интерфейса, но и на ниво база данни.

## 15. React-Specific Techniques

### React Hooks

В приложението се използват React Hooks, включително:

- `useState`
- `useEffect`
- `useContext`
- React Router hooks като `useParams` и `useNavigate`

`useState` се използва за управление на:

- form data;
- loading states;
- error states;
- филтри;
- UI състояния.

`useEffect` се използва при зареждането и обновяването на remote data, както и при authentication логиката.

`useContext` се използва за достъп до споделеното authentication състояние.

### Component Lifecycle

При mount на страници като Product Catalog, Product Details, Masters и Profile се извличат необходимите данни от Supabase.

При промяна на зависимост като route parameter или authentication state съответните React effects могат да се изпълнят отново и да обновят показаните данни.

При unmount React премахва съответния компонент от component tree при навигация към друга страница.

### Context API

Authentication информацията се управлява чрез `AuthContext`.

Контекстът предоставя информация и действия, свързани с:

- текущ потребител;
- authentication status;
- loading status;
- login;
- registration;
- logout.

Тази информация се използва от:

- Header;
- Route Guards;
- Profile;
- CRUD функционалности;
- Favorites;
- други authenticated части на приложението.

## 18. Error & Edge Case Handling

Приложението обработва различни error и edge cases.

### Authentication Errors

При неуспешен login или registration се визуализира съобщение за грешка.

### API / Data Errors

При грешка при заявка към Supabase се показва подходящо error състояние вместо приложението да се срине.

### Loading States

При извличане на remote data се използват loading състояния.

### Invalid Forms

Невалидните данни се проверяват преди изпращане.

### Missing Routes

Несъществуващ маршрут води към 404 страница.

### Unauthorized Operations

Route guards ограничават достъпа до private routes.

Owner проверките и Supabase RLS предотвратяват редактиране или изтриване на чужди записи.

### Delete Confirmation

Преди изтриване на продукт се изисква потвърждение.

## 19. Image Upload

При добавяне на продукт потребителят може да избере изображение от устройството си.

Изображението се качва в Supabase Storage, а публичният URL се записва към продукта.

При редактиране може да бъде качено ново изображение.

Профилните снимки също се качват в Supabase Storage.

Преди записване на нова профилна снимка се показва локален preview.

## 20. Typical User Flow

Примерен нормален user journey:

1. Посетител отваря началната страница.
2. Отваря каталога `Продукти`.
3. Използва търсене или филтри.
4. Отваря детайлната страница на продукт.
5. Разглежда профила на майстора.
6. Регистрира се или влиза в съществуващ профил.
7. Редактира своя профил и добавя профилна снимка.
8. Създава собствен продукт.
9. Редактира или изтрива свой продукт.
10. Разглежда чужд продукт и го добавя към любими.
11. Отваря страницата `Любими`.
12. При приключване използва `Изход`.

# Local Setup

## Клониране на repository

```bash
git clone https://github.com/DimitarMihaylov38/handmademaster-bg.git
```

## Влизане в проекта

```bash
cd handmademaster-bg
```

## Инсталиране на dependencies

```bash
npm install
```

## Environment Variables

Създайте `.env` файл в root директорията на проекта:

```env
VITE_SUPABASE_URL=YOUR_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY
```

Не трябва да се използва Supabase `service_role` secret във frontend приложението.

## Стартиране

```bash
npm run dev
```

Приложението по подразбиране се стартира на:

```text
http://localhost:5173/
```

## Production Build

```bash
npm run build
```
